telemetry: report the current release instead of the largest old sample

A minimum sample of 20 runs selected which release supplied quality rates. Under a
release per commit no release reaches it, so selection fell through to the largest
sample, which is always the oldest, and a superseded release's long-repaired outage
held the verdict at OUTAGE with no way for a fix to displace it.

Sample size is now a disclosure, not a selection gate: the newest release with
comparable completed runs supplies the rates and a thin sample is reported against
the window population. The outage trigger is a rate (CAIRN_OUTAGE_VISIBILITY_RATE,
default 25%) so one stray failure degrades rather than declares a total outage.

Per-release scoping is unchanged, so a repaired release still cannot be degraded by
an older release's faults.

Live: sample moved from 0.1.0+6ad0833 (Jul 30) to 0.1.0+13128b7; OUTAGE -> degraded.
Gates: 406 pass, 0 fail; tsc clean.
